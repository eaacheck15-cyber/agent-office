# 📦 ОБЛАКО ОТКРЫТЫХ ДАННЫХ (db-leaks)

Отдельное хранилище в офисе для скачанных данных из открытых источников.
Паук складывает сюда ТОЛЬКО то, что проходит правила — без мусора.

## 📁 Где
```
/root/office/db-leaks/<цель>/   →  на GitHub: db-leaks/
```

## ✅ ПРАВИЛА: ЧТО КАЧАЕМ (только данные, не мусор)

Файл скачивается в db-leaks ТОЛЬКО если выполняется ХОТЯ БЫ ОДНО:

| # | Правило | Пример |
|---|---|---|
| 1 | Расширение = данные | `.json .csv .sql .xlsx .xml .txt .zip .gz .yaml .db .sqlite .bak .dump .dat` |
| 2 | Content-Type = данные | `application/json`, `text/csv`, `application/sql`, `text/plain` (не html) |
| 3 | Тело = JSON/массив с признаками данных | начинается с `{` или `[` И содержит `"id"`, `"data"`, `"rows"`, `"users"`, `"email"`, `"amount"` |

## ❌ ЧТО НЕ КАЧАЕМ (мусор)

| # | Правило | Почему |
|---|---|---|
| 1 | **SPA-фолбэки (715 б у IIS)** | это один и тот же index.html админки, не данные |
| 2 | Файлы < 2 КБ | мелкие = пустые ответы/редиректы |
| 3 | Расширения: `.css .png .jpg .gif .svg .ico .woff .woff2 .ttf .map .min.js` | статика |
| 4 | HTML-страницы | витрины/админки, не данные |
| 5 | Ответы с ошибками (4xx/5xx) | нет данных |

## 🧠 Логика

```
URL доступен (200) → проверить _is_data_candidate(url, content_type, size, body):
  ├─ расширение данных?        → КАЧАЕМ
  ├─ content-type данных?      → КАЧАЕМ
  ├─ JSON-тело с признаками?   → КАЧАЕМ
  └─ иначе (html/статика/мелко) → ПРОПУСКАЕМ (мусор)
```
